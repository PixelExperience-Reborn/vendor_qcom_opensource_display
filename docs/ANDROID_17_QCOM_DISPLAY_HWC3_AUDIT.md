# PE-Reborn Android 17 — row 178: Qualcomm Display HWC3, Gralloc and mondrian

**Review date:** 2026-11-07. **Target:** independent AOSP17 PixelExperience-Reborn on POCO F5 Pro / Redmi K60, `mondrian` (SM8475, `taro`). **This is source-only review**: no actual full ROM build, vendor firmware, gralloc/Composer service runtime, device VINTF or panel validation.

## Engineering decision

**Retire the archived 2021 helper project `vendor/qcom/opensource/display` from the Android17 default source graph.** It contains only 18 files, not the actual composer/SDM display HAL. Its three `PRODUCT_PACKAGES` (`libqdMetaData`, `libgralloc.qti`, `libdisplayconfig.qti`) and Soong modules depend upon deprecated **Graphics Mapper HIDL 4.0** (`android.hardware.graphics.mapper@4.0`), **`vendor.display.config@2.0`** HIDL and `libhidlbase`. It imports a separate `vendor/qcom/opensource/commonsys-intf/display` Soong namespace. These are **not** a modern Android17 Composer3/Allocator/Mapper complete HAL and should not be treated as evidence that the old tree can render a frame on mondrian.

We found a newer **Qualcomm-derived** HWC3 AIDL/Gralloc source line hosted by Sony Open Devices: `sonyxperiadev/hardware-qcom-display`, `aosp/DISPLAY.LA.5.0.r1` (commit `baf61f736e2109522e3f72754ee7cfacbfa2dc6c`, tree `f35e03e1904a346fad8257321233a32650b4ee77`). It has **AIDL Composer3 V2/V3**, AIDL Allocator V2 and **Native Stable-C Mapper V5**, with older mapper/HIDL compatibility code. That is architecturally newer than the 2021 helper or historic 2023 `hardware/qcom-caf/sm8450/display` (HIDL Composer 2.4).

**However it is not a complete, verified SM8475 display stack:** The Sony source tree has 231 tracked files but **no `sdm/libs/` or `sde-drm/` source directories**, while its Composer needs `libsdmcore`, `libsdmutils`, `libsdmclient`, `libdrm`, `libdisplaydebug` and vendor AIDL display interfaces. Some could exist elsewhere in a complete downstream BSP or proprietary vendor image, but that dependency graph and binary ABI are **not verified here**. No independent ROM should enable this tree merely by adding the Git checkout.

A strictly **nondefault, source-only** experimental manifest `aosp17_pe_p2_qcom_display_aidl_candidate.xml` pins just the Sony-hosted modern source at `hardware/qcom/display` without replacing the official AOSP17 interfaces or active projects. This is the **preferred modernization direction for continued review**; it is a hold pending a compatible SDM/DRM source/vendor implementation and mondrian hardware evidence. Do not substitute an old sm8450 SDM tree without ABI review.

## Cross-branch 2026 SM8450 dependency finding

A Sony Open Devices **SoC-specific local manifest** names `vendor/qcom/opensource/display/sm8450` at `aosp/DISPLAY.LA.2.0.r1`. The exact pinned 2026-02-23 public snapshot `4744d4a2...` has **376 files** including `sdm/libs/core/Android.bp` and `sde-drm/Android.bp`. This is more up-to-date than our 2023 historical SM8450 SDM, and relevant to the hardware family. But its Composer `Android.bp` links `android.hardware.graphics.composer@2.1` through `@2.4` and `vendor.qti.hardware.display.composer@3.1`; its VINTF fragment still declares **HIDL `android.hardware.graphics.composer@2.4/IComposer`**. Gralloc still depends on HIDL Mapper4.

**Interpretation:** The "newest dated" source for *SM8450 SDM/DRM* is not an AOSP17 HWC3 AIDL implementation; the HWC3 AIDL source at `DISPLAY.LA.5.0.r1` is architecturally newer but missing its corresponding SDM/DRM implementation. The correct course is to find a **version- and vendor-ABI-matched modern SDM provider**, not cherry-pick `sdm/` into a different composer. Both sources are **comparisons only** until a PE-Reborn product and a real Xiaomi vendor/DRM contract exist.

Read-only reference: https://github.com/sonyxperiadev/vendor-qcom-opensource-display/tree/aosp/DISPLAY.LA.2.0.r1; Sony's source-only `qcom-sm8450.xml` reference does **not** authorize borrowing its device tree or firmware.

## Actual modern Composer, gralloc and VINTF details

- `composer/Android.bp` declares vendor binary **`vendor.qti.hardware.display.composer-service`**, with `composer3_defaults` selecting **`android.hardware.graphics.composer3-V2-ndk`** or **`...-V3-ndk`** and corresponding fragments `composer-service3_v2.xml` and `composer-service3_v3.xml`. The `composer_version` Soong value supports `v2`, `v3`, `v3_3`, `qmaa`; the actual source `config/display-product.mk` defaults to `v3` in its configuration, but only `v3_3` selects the V3 NDK branch in the observed defaults: **don't infer a runtime V3 service from a variable named v3**. The actual built/installed manifest must be checked.
- The v3 VINTF fragment advertises **`android.hardware.graphics.composer3` version 3 `IComposer/default`** and vendor display **color V1, postproc V1, config V12, AIQE V2**. v2 advertises composer3 version 2 and config V11 (without AIQE). **No Composer3 V5 source declaration** is present. AOSP17 interface V5 existence does not force vendors to implement V5, but acceptable V2/V3 fallback depends on Android17 VINTF/FCM, frozen AIDL/NDK and SurfaceFlinger requirements.
- `composer/service.cpp` registers the NDK Binder composer and vendor display config/AIQE interfaces. `composer/vendor.qti.hardware.display.composer-service.rc` runs as `system` in `class hal animation`, can restart `surfaceflinger` and uses `drmrpc` group and privileged scheduling. This must undergo an Android17 enforcing SELinux/cgroup/init audit; never copy it unreviewed.
- `gralloc/Android.bp` declares **`vendor.qti.hardware.display.allocator-service`** using `android.hardware.graphics.allocator-V2-ndk` and Stable-C **`mapper.qti`**. `gralloc/vendor.qti.hardware.display.allocator-service.xml` advertises **Allocator AIDL V2/IAllocator/default**. `gralloc/mapper.qti.xml` advertises **native mapper V5**, instance `qti`, not an AIDL mapper service. It also includes obsolete mapper HIDL4 modules: source coexistence must not be confused with an installed double mapper.
- The modern display source has references to `libsdmcore`, `libsdmclient`, `libsdmutils`, `libdrm`, display common/kernel headers and QTI proprietary display AIDL interfaces. A `repo sync` of **only** this repo cannot establish a complete Soong graph or a compatible binary. A separately pinned, authenticated modern SM8475-compatible SDM/DRM and target vendor dependency list is a **hard blocker** before making it active.
- `config/display-product.mk` copies calibration samples for **Visionox, Sharp, Sony and other panels**, generic HDR, DPPS, DSI/QSync and backlight settings; it also sets defaults like `ro.surface_flinger.has_HDR_display` and vendor display properties. They are platform examples, **not verified mondrian panel identities or calibrated values**. Never inherit it on POCO F5 Pro / Redmi K60 without reading the matching stock SKU's panel IDs and calibration. Wrong values can break brightness, color, refresh, doze/AOD or panel power management.

## Manifest ownership regression — corrected test anchor

The original PE AOSP17 source owner for `hardware/interfaces` is the **PE-Reborn GitHub repository `hardware_interfaces`** on `port/a17-hardware-interfaces-pe-20261103`, with pinned commit `735e364cbdd00b0d6e4dc33ea0866dbb6d971a11`. It replaces the initial `platform/hardware/interfaces` checkout in a reviewed stage. Therefore an adversarial test that tries to remove `platform/hardware/interfaces` from the **final** resolved P2 stage cannot succeed: the name is no longer present. The test now removes `hardware_interfaces` and checks that the global forbidden historical-repository-name guard rejects the injected `vendor_qcom_opensource_display` **before** the revision/owner pin rule. The first run incorrectly assumed the removed name was `platform/hardware/interfaces`; the second run used the correct PE owner but expected a later error message. Both mistakes were confined to adversarial-test expectations. This is a test correction for existing source-ownership protections, not a change to the selected AOSP17 interface, the modern Qualcomm candidate or the safe default.

## Device-specific bring-up / safety gates

1. Obtain matched stock `mondrian` vendor firmware evidence: panel supplier and DSI/DSC mode, display device tree/driver compatibles, DRM/SDM branch/ABI, GBM/UBWC, `/dev/dri`, GPU/Adreno/ion/dma-buf, gralloc metadata, 60/120 Hz modes, HDR/WCG/QSync, FOD and ESD recovery if supported. The old file name `display` and `taro` family are **not enough**.
2. Choose exactly **one** Composer3 `IComposer/default` service and one matching Allocator AIDL/Stable-C Mapper. Do not install legacy HIDL Composer2/Mapper4 and AIDL Composer3 together accidentally. Match SurfaceFlinger, vendor display config/color, VINTF/FCM and frozen AIDL versions. Preserve PE AOSP17 `hardware/interfaces` V5/V3 canonical owners.
3. Verify Soong/NDK and proprietary ELF `DT_NEEDED`, SDM/DRM/source/provider symbols, mapper/gralloc5 handle metadata, protected layers, HDCP, hardware overlays, HDR and secure buffers. Fail closed if any required libraries/interfaces are absent or unresolved. Do not enable secure/protected compositor flags without DRM authorization and tests.
4. Test real panel bring-up, clean boot, screen wake/sleep, brightness/auto-brightness, smooth refresh switching, SF fences, HWC composition, DRM modeset, calibration, video/camera buffer sharing, screenshot/virtual display/recording, doze/AOD, battery/thermal and SF/DRM crash recovery; run **`VtsHalGraphicsComposer3_TargetTest`**, allocator and stable-C mapper VTS, plus relevant CTS/gfxbench.
5. Keep independent PE-Reborn product/device trees; LF52406 LineageOS references only exceptional last-resort **read-only hardware evidence**. Do not copy Lineage display overlays/vendor blobs/panel config or Sony Xperia calibration and claim the ROM works on mondrian.
6. No full build, physically tested display, modem/GPU runtime or completed Android17 ROM is claimed by this row. Static CI can only validate source identity, HAL boundaries, candidate isolation and the absence of false merges.
